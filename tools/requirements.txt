# Python deps for the EMStudio batch-interop tools (graphml2em.py,
# em2graphml.py, em_bridge.py). Install with:
#     pip install -r tools/requirements.txt
#
# s3Dgraphy is the reference implementation of the EM language (ADR-001):
# all GraphML <-> em.json conversion runs here, never in the frontend.
#
# Version policy: pin an EXACT release. pip only resolves a .devN
# pre-release when the version is pinned exactly (or with --pre), so a bare
# `s3dgraphy` would silently prefer the latest STABLE and miss dev fixes.
#
# NOTE: the dev line pinned below tracks the published PyPI dev. Local
# working-tree changes to s3Dgraphy are NOT on PyPI — for those, run the
# tools against a checkout instead (editable install or the --s3dgraphy
# flag / dev.sh, which puts ../s3Dgraphy/src on sys.path). Bump this pin
# after publishing a new dev that contains the changes you depend on.
#
# The EXTRAS are not cosmetic — em_bridge.py needs both:
#   [geo] → pyproj, for /reproject and /georeference-scene (the map for any
#           projected CRS). pyproj's wheels bundle PROJ, so no system GDAL.
#   [rdf] → rdflib, for /export-ttl.
# Without them those endpoints answer 501 (honestly, but uselessly). dev12 is
# the first release that declares [geo]; dev11 and older silently ignored it.
s3dgraphy[geo,rdf]==1.6.0.dev21

# Hard runtime deps of the s3Dgraphy importer/exporter used by the tools.
lxml>=4.9
pandas>=1.3
# GraphMLImporter.parse() (used by graphml2em.py and the bridge's
# /import-graphml) pulls in s3dgraphy.sync.rapporti, which requires SQLAlchemy
# — it's the s3dgraphy [sync] extra, now a hard dep for GraphML *import*.
sqlalchemy>=2.0

# ── figures in the narrative exports (20 Aug 2026) ───────────────────────────
# The CLIENT renders the visual embeds (a matrix is drawn by the layout engine,
# and the engine is in the client — see s3dgraphy.narrative.bake.figure_key) and
# posts them as SVG. What each format can embed differs, so the bridge converts:
#   html · ipynb → the SVG as it is
#   docx         → PNG (python-docx embeds raster only)
#   latex        → PDF (\includegraphics under pdflatex takes PDF/PNG/JPG)
# cairosvg does both conversions without a browser, which is why it is here and
# not a headless Chrome. It needs libcairo present (brew install cairo; the wheel
# does not bundle it).
#
# OPTIONAL, by the same rule as rdflib/pyproj: absent, the bridge falls back to
# the `rsvg-convert`/`inkscape` binary if the machine has one, and otherwise the
# figures stay the placeholders they were — the export still happens, per figure.
# HTML and Jupyter need none of this: they take the SVG directly.
cairosvg>=2.7

# Word (.docx) export. The PyPI package is `python-docx` and the import is
# `docx` — there is an unrelated `docx` on PyPI, and installing that one is the
# classic way to get "no module named docx" while pip says it is installed.
#
# s3Dgraphy declares it as the OPTIONAL `[docx]` extra and degrades without it
# (MissingDependency → the bridge answers 501, honestly). That is right for a
# library; it is not right for THIS bridge, which is the thing the app's
# «Esporta ▸ Word» button talks to. Measured 20 Aug 2026: the button answered
# "docx export unavailable in this build" because the interpreter running the
# bridge had cairosvg (listed here) and not python-docx (not listed) — an
# asymmetry, not a decision.
#
# Pure Python, no native library, nothing to bundle by hand: unlike cairosvg
# there is no reason for this one to be conditional anywhere.
python-docx>=1.1

# ── installing these in a CHECKOUT venv ──────────────────────────────────────
# `pip install -r tools/requirements.txt` inside `../s3Dgraphy/.venv` would also
# install the PINNED `s3dgraphy==` above from PyPI, shadowing the editable
# checkout that venv exists for — i.e. the bridge would stop seeing the library
# you are editing. In that venv install the deps WITHOUT the pin:
#
#     ../s3Dgraphy/.venv/bin/pip install python-docx cairosvg
#
# and leave the `-e .` install alone. The pinned line above is for a venv that
# has no checkout (a packager, a CI runner).
